# Troubleshooting

## Directory sync

**`[sync] dir` is not configured`**

```bash
kimetsu config set sync.dir /path/to/shared/kimetsu-sync
kimetsu config set sync.machine_id my-laptop
kimetsu brain sync --status
```

Both machines must use the **same** `sync.dir` and **different**
`machine_id` values.

**Peers show up empty / nothing pulls**

1. Confirm the shared folder actually contains `<dir>/<other-machine-id>/`
   batch files (Dropbox/Syncthing lag is the usual cause).
2. Run `kimetsu brain sync` on the writer first, then on the reader.
3. Check `kimetsu brain sync --status` for cursors and `pending_pull`.

**Conflicts after concurrent edits**

```bash
kimetsu brain memory conflicts
```

Directory sync is event-log replication. Concurrent supersedes can leave a
conflict for you to review; they are not silently dropped.

**Sync vs pack**

`kimetsu brain sync import` refuses a `kimetsu_pack` file. Packs go through
`kimetsu brain import`. Sync batches go through `kimetsu brain sync`.

## Signed packs

**Import says the signer is not trusted**

Add the pack's `signer` public key to `~/.kimetsu/trust.json` under the mount
you are importing into, or pass `--trust-store`. Without that, a valid
signature is quarantined on purpose.

**`--sign-key` errors**

- Requires `--scope`.
- Does not take `--kind`.
- Key file must be 64 hex chars or `{"kimetsu_signer":1,"secret_key":"…"}`.

**URL imports land in quarantine**

That is the default for `http(s)://` sources. Review with
`kimetsu brain memory accept`, or pass `--no-quarantine` only when you trust
the source.

## Coming soon: peer-to-peer (QUIC)

There is no `kimetsu invite`, `join`, `network`, `bus`, or `roster` command in
the released CLI. The iroh QUIC bus lives in `kimetsu-bus` and is exercised by
tests and operator examples only. When a user-facing dial path ships, expect
UDP (not TCP) between peers, and the usual home-NAT / firewall / WSL caveats.
Until then, use directory sync or signed pack files — they do **not** need
UDP.

## Still stuck

```bash
kimetsu doctor
kimetsu brain sync --status
kimetsu plugin status
```

For server-based sharing instead of a shared folder, see
[Kimetsu Remote](/docs/remote).
